02 / Référentiel

Un Skill pour chaque besoin.

Six étapes principales, un audit transverse et trois extensions. Installez uniquement les compétences utiles à votre projet.

  • 00
    Cadrer ↗project-discovery-validation

    Vérifier le besoin, confronter les hypothèses et définir un MVP.

  • 01
    Spécifier ↗product-spec-docs

    Règles métier, parcours, critères d’acceptation et décisions.

  • 02
    Concevoir ↗ux-ui-design

    Architecture de l’information, accessibilité et interfaces utilisables.

  • 03
    Structurer ↗api-data-architecture

    Modèles de données, contrats API, migrations et confidentialité.

  • 04
    Construire ↗clean-code-security

    Code maintenable, sécurité et hygiène du dépôt.

  • 05
    Vérifier ↗qa-perf-observability

    Tests, performances, résilience et observabilité.

  • ↗
    Auditer ↗full-project-audit

    Inspection indépendante et plan de remédiation priorisé.

  • E1
    Publier ↗release-deployment

    Build, version, livraison et retour arrière.

  • E2
    Maintenir ↗maintenance-incident

    Triage, incidents, restauration et suivi.

  • E3
    Gouverner ↗oss-governance

    Licences, dépendances et contributions open source.

Comment les règles sont-elles justifiées ?

Le référentiel distingue notamment normes, résultats scientifiques, recommandations empiriques et conventions de conception. Une règle n’est pas une preuve de conformité d’un produit. Les tests et le contexte déterminent ce qui est applicable.

03 / Installation

Démarrer sans infrastructure.

Récupérez le dépôt, puis copiez les dossiers de Skills souhaités dans le répertoire reconnu par votre assistant.

Récupérer les fichiers

git clone https://github.com/Karmadibsa/agent-skills-suite.git

Gardez le fichier SKILL.md et son dossier references/ ensemble.

Choisir le dossier de destination

Claude Code
.claude/skills/
Cursor
.cursor/skills/
Codex
.agents/skills/

Les modalités dépendent de la version et de l’environnement de l’assistant. Pour ChatGPT, consultez les possibilités d’installation disponibles dans votre interface.

04 / Contribution

Bug ou idée ?

Préparez un retour contextualisé et relisez-le avant de le publier sur GitHub. Le site ne collecte ni n’envoie automatiquement vos messages.

Ne saisissez aucune information personnelle, confidentielle ou liée à une faille de sécurité dans un ticket public.

Aperçu avant publication

Le retour préparé apparaîtra ici. Vous choisissez ensuite de le copier ou de le publier.

Ouvrir un ticket GitHub ↗

Pour une vulnérabilité, privilégiez un signalement privé au mainteneur plutôt qu’un ticket public.
