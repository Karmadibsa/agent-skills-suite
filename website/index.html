Avec project-discovery-validation

Avant de coder, trois objections.

  • Chatbot : quel besoin couvre-t-il que la recherche ne couvre pas ? Il ajoute un coût d'API récurrent et envoie des données financières à un tiers N1. Alternative plus simple : catégorisation automatique en local.
  • Badges : utile seulement si l'abandon est le problème observé N6.
  • Fil social : hors du besoin principal, risque de confidentialité.

Proposition : tester la catégorisation avec 5 utilisateurs. Critère d'abandon : moins de 3 l'utilisent après une semaine.

  • Alternative plus simple
  • Niveau de preuve

Le bon contexte, au bon moment

Un skill ne charge que ce dont la tâche a besoin. Votre assistant garde sa fenêtre de contexte pour votre code.

  1. ~100 tokens

    Découverte

    Au démarrage, l'assistant lit seulement le nom et la description des onze skills.

  2. 1 fichier

    Activation

    Votre demande correspond à un skill : il charge son SKILL.md, le workflow et les garde-fous.

  3. 1 fiche

    Référence ciblée

    La table de routage lui indique la seule fiche utile : formulaires, migrations, OWASP…

Un profil par projet

Onze skills, utilisables seuls

Le parcours ci-dessous est un ordre conseillé, pas une obligation. Si un livrable amont manque, le skill le reconstitue depuis votre code et le signale.

  1. start-hereDiagnostique le projet, crée le profil, choisit le skill suivant

    À utiliser en premier sur un projet, ou quand vous ne savez pas quel skill appeler.

    Utilise le skill start-here.
    Lire le SKILL.md
  2. project-discovery-validationChallenge l'idée, analyse l'existant, construit la roadmap

    Jobs-to-be-Done, Kano, RICE, contre-argument obligatoire et alternative plus simple, jalons jusqu'au MVP.

    Utilise project-discovery-validation. Mon idée : …
    Lire le SKILL.md
  3. product-spec-docsÉcrit une spécification que l'IA peut exécuter

    Règles métier verrouillées, user stories, scénarios Gherkin, ADR, CHANGELOG et découpage en lots atomiques.

    Utilise product-spec-docs pour spécifier le MVP.
    Lire le SKILL.md
  4. ux-ui-designConçoit et audite les écrans : WCAG 2.2, mobile, anti-slop

    Quatorze fiches : lois cognitives, accessibilité, formulaires, navigation, dataviz, direction artistique, module « Bug ou idée ? ».

    Utilise ux-ui-design pour revoir cet écran.
    Lire le SKILL.md
  5. api-data-architectureSchéma, migrations sans perte, contrats d'API, RGPD

    Normalisation, UUID, dates UTC, montants exacts, erreurs RFC 9457, pagination bornée, minimisation des données.

    Utilise api-data-architecture pour cette migration.
    Lire le SKILL.md
  6. clean-code-securityCode simple, OWASP, secrets, dépôt propre

    Séparation domaine et interface, validation des entrées, aucun secret en dur, aucun fichier _old, scripts de lancement en une commande.

    Utilise clean-code-security pour refactoriser ce module.
    Lire le SKILL.md
  7. qa-perf-observabilityTests accessibles, Core Web Vitals, logs sans données perso

    Tests E2E par rôles ARIA, axe-core, budgets de performance, sobriété RGESN, logs structurés.

    Utilise qa-perf-observability pour tester ce parcours.
    Lire le SKILL.md
  8. release-deploymentVersions SemVer, builds reproductibles, rollback

    CHANGELOG, tags, CI gratuite, déploiement Netlify, Vercel ou Cloudflare Pages, plan de retour arrière.

    Utilise release-deployment pour préparer la 1.2.0.
    Lire le SKILL.md
  9. maintenance-incidentIncidents, correctifs minimaux, sauvegardes

    Triage par priorité, reproduction avant correction, sauvegarde préalable, test de non-régression.

    Utilise maintenance-incident : l'export plante.
    Lire le SKILL.md

Une préférence n'est pas une norme

Chaque règle porte son niveau de preuve. En cas de conflit, le plus solide l'emporte.

  1. N1Obligation légale ou normeRGPD, WCAG 2.2 AA
  2. N2Résultat scientifiqueFitts, Hick-Hyman, ACID
  3. N3Standard ou terrain vérifiéOWASP, NN/g
  4. N4Convention d'ingénierieSemVer, RFC 9457
  5. N5Choix contextuelstack, direction artistique
  6. N6Hypothèse à testerintuition, estimation

Installer en une commande

Toute la suite ou un seul skill. Gratuit et open source ; votre assistant et votre hébergeur peuvent avoir leurs propres coûts.

CLI skills

$npx skills add Karmadibsa/agent-skills-suite
$npx skills add Karmadibsa/agent-skills-suite --skill ux-ui-design

Mise à jour : npx skills update

Claude Code

$git clone https://github.com/Karmadibsa/agent-skills-suite.git
$cp -r agent-skills-suite/skills/* .claude/skills/

Pour tous vos projets : ~/.claude/skills/

Cursor et autres outils

Copiez le contenu de skills/ dans .cursor/skills/ pour Cursor, ou dans .agents/skills/ pour les outils qui suivent le format universel. Gardez chaque SKILL.md avec son dossier references/.
